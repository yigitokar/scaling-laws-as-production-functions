## Sample A: Epoch universe (open and closed)

Start: 2,070 rows of `all_ai_models.csv` whose `Domain` contains "Language". Exclusions (counts): derived model, i.e. a
non-empty `Base model` (fine-tunes, continued pretraining, post-training updates) 531; N missing 361; release date
outside 2019-01..2026-09 234; D not recoverable 224; multimodal domain (D would include image/audio tokens) 131;
benchmark-scale research model (unique corpus < 5e9 tokens: WikiText/PTB/enwik8-type runs) 100; encoders
(BERT/RoBERTa/ELECTRA/DeBERTa/XLM-R/embedding models) 34; encoder-decoders and seq2seq dialogue models (T5, UL2,
BART, AlexaTM, NLLB, PLATO, BlenderBot...) 24; post-trained variants identified by name 16; MoE without a recoverable
active-parameter count 27; implausible epochs (> 20) or D/N > 30,000 15; 29 manual exclusions (post-training
updates such as Llama 3.3 70B or DeepSeek-V3 (Mar 2025); systems-paper benchmark runs; LLaDA (diffusion LM);
GPT-4 (leaked figures); Qwen2-57B-A14B (upcycled); Stable LM 2 12B (D ambiguous); encoders Epoch lists as LMs).
Kept: 342. `core` = 6ND >= 1e21 FLOP, Epoch confidence not "Speculative", not code-specialised: 287 (222
open-weight, 65 closed). [Review] Trends, rivals and the aggregate use the production-scale universe `prod` =
Sample-A core rows not matched to Sample B plus Sample-B general-purpose models with 6ND >= 1e21 (335 models in
2019-2026; the builder had not applied the threshold to Sample B).

- **N.** Epoch `Parameters`. MoE (name/notes patterns): active parameters from the name (A3B, A22B), else from
  `Parameters notes` ("32B activated", "Activated Parameters per Token: 45.9B"; the smallest figure below the total),
  else C/(6D) when compute is operation-counted and not speculative; K-EXAONE's 23B active is entered by hand.
- **D (tokens).** `Training dataset size (total)` x `Epochs` (missing epochs = 1). Comma-joined alternatives: the
  maximum. Epoch records older language datasets in WORDS (0.75 words/token). Rule: if the dataset-size notes contain a
  words conversion and operation-counted compute implies C/(6ND) in [1.2, 1.45], use C/(6N) (4 rows); if the notes
  show the token-to-word conversion but compute is uninformative, multiply by 4/3 (3 rows); if C/(6ND) is about 1 the
  value is kept as tokens (8 rows); otherwise kept (32 rows whose notes merely mention words). If the dataset size is
  missing, D = C/(6N) when compute is operation-counted and confidence is Confident/Likely (67 rows). Primary-source
  corrections (`build_choices.EPOCH_D_FIX`): GPT-3 175B D = 300B tokens (Brown et al. 2020, Table D.1; Epoch records
  238B words x 0.6 epochs). [Review] Five more, each documented in Epoch's own notes and found by comparing D with
  Epoch's operation-counted/reported compute: GLM-130B 152B -> 400B; Cerebras-GPT-13B 177B -> 257B and BloombergGPT
  455B -> 569B (Epoch's dataset size is already tokens seen, so size x epochs double-counted); Polyglot-Ko-12.8B
  96B words -> 167B tokens; GPT-SW3 509B -> 102B (97,000 steps x 512 x 2,048; x5 epochs over-counted).
- **D/compute diagnostic [Review].** `C_D_ratio` = C/(6ND) and `D_C_mismatch` = |ln C_D_ratio| > ln 1.5 with
  operation-counted or reported compute. 11 production-scale rows remain flagged (e.g., CPM-Ant/Bee, whose Epoch
  compute uses 10x the parameter count; AFM-on-device, whose compute includes the teacher); trends are reported with
  and without them.
- **Known weaknesses.** Closed-model N and D are often estimates (Epoch confidence grades are kept); D-from-compute
  rows inherit Epoch's compute assumptions; the words/tokens rule is heuristic. Sample A is therefore used only for
  trends and the aggregate, with Sample B as the verified core.

## Units and conventions (read before using the wedges)

- w uses the technology's own conventions: total N incl. embeddings (Chinchilla/Besiroglu/Hoffmann, Gadre, Farseer
  incl.-emb. row, Meta), non-embedding N (Farseer headline row) or N minus the input embedding (OLMo ladder).
- D is in each model's own tokenizer's tokens; technologies are in their sweep's tokens. A 20% tokenizer difference
  moves ln w by beta x 0.18 ~ 0.07 (about 7%).
- Elasticities of the reported wedge with respect to input errors: d ln w / d ln D = beta ~ 0.37 and
  d ln w / d ln N = -alpha ~ -0.35 (reference technology). A 10% error in D moves w by about 4%.
